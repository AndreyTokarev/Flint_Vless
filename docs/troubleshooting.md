## Что проверить в первую очередь

Один запрос заменяет половину догадок:

```sh
ssh root@192.168.8.1 'flint-node list; flint-dns; flint-tg state; flint-adblock state'
```

И журналы:

```sh
logread -e xray          # Xray: подключения, ошибки REALITY
logread -e flint-watchdog   # срабатывания автопереключения
cat /etc/xray/watchdog-last # последнее срабатывание
cat /etc/xray/sub-checked   # когда проверялись подписки
```

## Таблица симптомов

| Симптом | Что проверить |
|---|---|
| `VPN: FAIL` в конце установки | жива ли подписка (вкладка «Подписки»); правильный ли `VLESS_UUID` для строк `nodes.conf`, вписанных вручную; живой ли сервер `DEFAULT_NODE` (попробуйте другой: `flint-node <код>`); `logread -e xray` |
| `DNS: FAIL` | `/etc/init.d/flint-doh restart`, затем `nslookup youtube.com 127.0.0.1`; работает ли интернет на роутере |
| Панель не открывается по `vpn.lan` | откройте `http://192.168.8.1:81/`; на устройстве отключите «Частный DNS» / DoH; `/etc/init.d/flint-ui restart` |
| Интернет пропал после смены сервера | сервер не отвечает — выберите другой или включите автопереключение; в крайнем случае выключите VPN кнопкой на «Статусе» |
| Сервер не подключается, хотя в Happ работает | у провайдера сменились ключи или SNI — «Подписки → Обновить все подписки сейчас» |
| Подписка не добавляется | «не скачалась» — откройте ссылку в браузере, проверьте интернет на роутере; «нет поддерживаемых серверов» — в подписке нет VLESS + REALITY (VMess, Trojan, Shadowsocks, XHTTP не поддерживаются) |
| Российский сайт открывается через VPN | нет баз geoip/geosite (тогда режим `global`): `flint-geo-update`; или добавьте сайт в «Напрямую» |
| `opkg install ... failed` | `/tmp/flint-opkg.log`; есть ли интернет на роутере; положите Xray в `backup/bin/xray` |
| Сайт или приложение сломалось при включённой блокировке рекламы | выключите блокировку и проверьте; если дело в ней — разрешите домен в «Сайтах без блокировки» (подсказка — в «Недавно заблокировано») или внесите устройство в «Устройства без блокировки» |
| Реклама на устройстве не блокируется | на устройстве выключите «Частный DNS», DoH в браузере и VPN-клиент (Happ и т. п.); проверьте, что устройство не в исключениях |
| Не открывается NAS или другое устройство основной сети | найдите его в списке клиентов основного роутера: возможно, после перезагрузки у него новый адрес. Закрепите адрес (резервирование DHCP или вручную на устройстве) и поправьте имя на вкладке «DNS → Локальные имена» |
| Telegram не подключается через прокси | «Telegram → Проверить прокси»: если строки `[FAIL]` у всех путей — включите резерв через Cloudflare или выберите путь «Через VPN». На устройстве выключите VPN-клиент; после смены порта, маскировки или секрета добавьте прокси в Telegram заново. «Включён, но не запущен» — выключите и включите прокси снова |
| Прокси «включён», но не работает, порт 443 | порт 443 на роутере занят nginx из прошивки. Верните порт прокси на 1443: `flint-tg port 1443; flint-tg on` |
| Реклама осталась на ВКонтакте, YouTube и т. п. | она идёт с того же домена, что и контент, и DNS-блокировкой не убирается — поставьте в браузер uBlock Origin (см. [Где реклама останется](dns-adblock.md#где-реклама-останется)) |
| После обновления прошивки VPN и панель пропали | обновляли без «Сохранить настройки» — `.\restore.ps1 -Full`; если с ней — повторите деплой, настройки в `/etc/xray` сохранились (см. [Обновление прошивки](maintenance.md#обновление-прошивки)) |
| На вкладке «Статус» вместо адресов `n/a` | роутер не смог получить свой внешний адрес: `curl -s -m 8 https://ifconfig.me` на роутере. Если сервис недоступен, укажите свой в `IP_LOOKUP` (`/etc/xray/flint.env`), например `https://api.ipify.org` |
| Нужно понять, что происходит | `flint-node list`, `logread -e xray`, `cat /etc/xray/sub-checked`, `cat /etc/xray/watchdog-last` |
| Защищённый DNS перестал отвечать, смена DoH-сервера не помогает | блокируют по имени резолвера: перебирать серверы внутри DoH бессмысленно. Переключитесь на DNSCrypt или на режим «через туннель» (см. [Если перестал работать защищённый DNS](dns-adblock.md#если-перестал-работать-защищённый-dns)) |

## Смена сервера идёт долго или не срабатывает

Переключение сервера перезапускает Xray, а Xray занимает порт перехвата (**12345**) **без** `SO_REUSEADDR`. Сокеты, которые устройства оставили в состоянии `TIME_WAIT` (ядро держит их около минуты, на активной сети их бывает 12–13 одновременно), не дают новому процессу занять порт: в журнале видно `address already in use`, хотя никто порт не слушает. Принудительно убрать эти сокеты нельзя — `conntrack` не отслеживает перенаправленный трафик локальной сети, `ss -K` в этой прошивке нет, `tcp_tw_reuse` влияет только на исходящие соединения, а Xray 26 игнорирует ключ `reusePort`.

Что с этим делает роутер: ждёт освобождения порта четырьмя кругами по минуте и только потом сдаётся. Если сдался — **конфиг и прежний сервер остаются на месте**, а в панели видно сообщение; повторите переключение через минуту-другую, когда сокеты истекут.

Что можно сделать самому:

- подождать минуту и повторить — чаще всего этого достаточно;
- уменьшить число одновременных подключений в момент переключения (пауза в загрузках и видео);
- если переключения мешают часто, включите автопереключение — тогда сервер меняет watchdog, а не вы, и он делает это в тот момент, когда туннель всё равно не работает.

Отдельно: **watchdog не трогает свежую смену сервера две минуты** (`/etc/xray/switch-at`). Иначе он видел бы краткий обрыв при перезапуске, считал новый сервер мёртвым и уводил бы с него — панель показывала бы прежний сервер.

## Забыли PIN

Посмотреть текущий:

```sh
ssh root@192.168.8.1 "grep UI_PIN /etc/xray/flint.env"
```

Задать новый (здесь `1234`, только буквы и цифры) — действует сразу, перезапускать ничего не нужно:

```sh
ssh root@192.168.8.1 "sed -i '/^UI_PIN=/d' /etc/xray/flint.env && echo UI_PIN=1234 >> /etc/xray/flint.env"
```

Впишите его и в `config/flint.env`, иначе следующий деплой вернёт прежний PIN. Или просто повторите деплой — PIN станет таким, как в `config/flint.env`.

## Устройства обходят роутер

- **Android:** *Настройки → Сеть → Частный DNS → Выкл.*, иначе телефон обходит DNS роутера.
- **Windows:** в свойствах Wi‑Fi *Назначение DNS → Автоматически (DHCP)*; иначе включённый DoH обходит DNS роутера и локальные имена (`nas01`) не резолвятся.
- **Браузеры** с включённым «безопасным DNS» (DoH) тоже обходят DNS роутера — гео-фильтр и свои сайты по доменам при этом продолжают работать (Xray определяет домен по TLS), а локальные имена и блокировка рекламы — нет.
- **VPN-клиент на устройстве** (Happ, v2rayN, Hiddify) заворачивает весь трафик в свой туннель: не работают ни VPN роутера, ни блокировка, ни свои сайты. За Flint такой клиент не нужен — выключите его.

## Ограничения

- **Только TCP.** Через VPN идёт TCP; QUIC (UDP 443) блокируется, чтобы браузеры перешли на TCP. Остальной UDP (игры, звонки в некоторых приложениях) идёт напрямую. Устройства без VPN сохраняют QUIC.
- **IPv6 не туннелируется.** Если основной роутер раздаёт IPv6, отключите его для сети Flint, иначе часть трафика пойдёт мимо VPN.
- **Xray.** В комплекте закреплён релиз `v26.3.27` (`XRAY_VERSION`), он ставится с проверкой SHA-256, а прежний бинарник остаётся в `/usr/bin/xray.previous`. Это важно не только ради новых транспортов: версии ниже v25.6.8 не имитируют post-handshake записи сайта-прикрытия, и REALITY в них отличим активным зондированием. Обновлять нужно **и сервер**: если сервер провайдера старше v25.6.8, обновление на роутере само по себе ничего не меняет. Транспорт XHTTP на роутере работает, но требует поддержки на стороне сервера.
- **Панель — для домашней сети.** Она работает по HTTP, PIN передаётся в адресе запроса. Не открывайте порт 81 в интернет.
- **Смена настроек VPN прерывает соединения на несколько секунд.** Перезапуск Xray нужен, чтобы применить новый конфиг. Часть изменений применяется без перезапуска: свои сайты, устройства без VPN, списки и правила блокировки, DNS, локальные имена.
