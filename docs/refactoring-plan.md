# План устранения проблем качества кода

План по находкам из [code-quality-audit.md](code-quality-audit.md). Цель — упростить код, **не меняя поведения**: что видит пользователь в панели и что делает роутер, остаётся прежним, кроме мест, оговорённых явно.

## Порядок и версии

| Этап | Находки | Объём | Риск | Версия |
|---|---|---|---|---|
| 0. Проверочные сценарии в репозитории | — | малый | нет | без выпуска |
| 1. Один владелец выбора сервера | 1, 2 | малый | низкий | 1.1.1 |
| 2. Общая библиотека `lib.sh` | 4 | малый | низкий | 1.1.1 |
| 3. Мелочи | 6 | малый | низкий | 1.1.1 |
| 4. Разгрузка `panel.cgi` | 5 | средний | средний | 1.1.2 |
| 5. Файл на каждый источник серверов | 3 | крупный | средний | 1.2.0 |

Этапы 1–3 — чистый рефакторинг, их можно выпустить одной патч-версией. Этап 5 меняет раскладку файлов на роутере и в бэкапе, поэтому это минорная версия с переносом старых данных.

Каждый этап — отдельный коммит (или несколько), после каждого: деплой на роутер, прогон сценариев этапа 0, запись в `CHANGELOG.md` / `CHANGELOG.en.md`.

## Этап 0. Проверочные сценарии в репозитории

Сейчас сценарии, которыми проверялся режим без серверов, лежат во временной папке компьютера. Без них рефакторинг вслепую.

**Шаги**
1. Создать `tests/router/` со сценариями, запускаемыми на роутере по SSH:
   - `empty.sh` — установка без `nodes.conf` и `SUB_URL`; проверка: Xray не запущен, нет перехода в цепочку `XRAY`, нет запрета QUIC, нет задания cron для подписок, интернет напрямую работает, панель показывает «Серверов пока нет»;
   - `subscription.sh` — добавление подписки из пустого состояния → VPN работает; удаление последней подписки → снова прямой выход;
   - `own-server.sh` — первым добавлен свой сервер → VPN работает; удаление → прямой выход;
   - `failover.sh` — исчезновение текущего сервера после обновления подписки → переключение на первый.
2. Каждый сценарий сохраняет состояние роутера (`/etc/xray/*`) в начале и возвращает его в конце, не печатает ссылки, UUID и PIN.
3. Обёртка `tests/run.ps1` / `tests/run.sh`: заливает сценарии и запускает их.

**Готово, когда** все сценарии проходят на текущем коде и роутер после них в исходном состоянии.

## Этап 1. Один владелец выбора сервера (находки 1, 2)

**Шаги**
1. `flint-node`:
   - `apply` без аргумента решает сам: сервер из `current-node`, если он есть в списке; иначе первый с сообщением «Текущего сервера больше нет, переключаюсь на …»; иначе режим без серверов (как сейчас);
   - `use <код>` и `flint-node <код>` остаются строгими: неизвестный код — ошибка;
   - сообщение о переключении переезжает сюда из `flint-sub-update`.
2. `flint-sub-update`, `commit()`: заменить проверку текущего сервера и `flint-node "${cur:-apply}"` на `flint-node apply`.
3. `flint-custom`, `del`: заменить поиск первого сервера и `"${first:-apply}"` на `flint-node apply`, если удалён текущий.
4. `install.sh`: блок выбора сервера →
   ```sh
   flint-node use "$DEFAULT_NODE" 2>/dev/null || flint-node apply
   ```
   Проверка перед гео-файлами (`[ -z "$(flint-node codes)" ] || flint-node apply`) уходит: `apply` в режиме без серверов и так ничего не ломает; повторное сообщение подавить, выводя его только при смене состояния.
5. Признак «серверов нет» = нет `/etc/xray/config.json`:
   - `firewall.user`: условие прямого выхода `vpn-state = off || [ ! -s /etc/xray/config.json ]`; переменная `$servers` остаётся только для правил `RETURN`;
   - `flint-watchdog`: `[ -s /etc/xray/config.json ] || exit 0` вместо `flint-node codes`;
   - `install.sh`: одна проверка — в итоговой части, для сообщения.

**Проверка:** сценарии этапа 0; дополнительно — `flint-node xx` с несуществующим кодом по-прежнему печатает `Unknown: xx`.

**Готово, когда** в коде нет `:-apply`, выбор первого сервера встречается только в `flint-node`, а `flint-node codes` для проверки пустоты не используется.

## Этап 2. Общая библиотека `lib.sh` (находка 4)

**Шаги**
1. Новый `kit/files/usr/share/flint/lib.sh`:
   - `t <ru> <en>` — язык из `FLINT_LANG`, затем `UI_LANG`, затем русский;
   - `node_lines <файл>...` — строки серверов без комментариев и пустых строк (с защитой от вызова без файлов);
   - `host_of <url>` — хост из ссылки.
2. Подключить в `flint-node`, `flint-sub-update`, `flint-watchdog`, `flint-adblock`, `flint-custom`, `firewall.user` (`. /usr/share/flint/lib.sh`) и убрать локальные копии, включая встроенный `if` с переводом в `flint-node`.
3. `install.sh`: копировать `lib.sh` вместе с `vless.awk`.
4. Демо-скрипт для скриншотов: подменять путь к `lib.sh`.

**Готово, когда** `t()` определена один раз, регулярное выражение фильтра комментариев встречается один раз, сценарии этапа 0 проходят.

## Этап 3. Мелочи (находка 6)

1. `install.sh`: загрузка подписки при пустом списке —
   ```sh
   # No servers yet but SUB_URL is set: fetch them now.
   [ -n "$(flint-node codes)" ] || flint-sub-update >/dev/null 2>&1 || true
   ```
   Проверка `flint-sub-update list` не нужна: без подписок команда сама отвечает «Подписок нет» и ничего не делает. Здесь именно список серверов, а не `config.json`: при первой установке с готовым `config/nodes.conf` конфига ещё нет, а скачивать подписку не надо.
2. `flint-sub-update`: переименовать `status()` → `last_check()` и `sub_status()` → `set_sub_status()`, чтобы имена говорили, что пишут; файлы состояния не объединять — у них разный смысл (общая последняя проверка и состояние каждой подписки).
3. `flint-sub-update`, `same()`: вынести `strip` на верхний уровень.

## Этап 4. Разгрузка `panel.cgi` (находка 5)

**Шаги**
1. **CSS** → `kit/files/www/flint/panel.css`, в разметке `<link rel=stylesheet href=/panel.css>`; `install.sh` копирует файл; демо-скрипт копирует его рядом с HTML.
2. **Диспетчер действий:** формы передают `a=<действие>` (`node`, `routing`, `vpn`, `subadd`, `subsave`, …); вместо 26 веток `elif` — один `case "$a" in ... esac`. Значения параметров остаются прежними. Ссылки и формы обновить в одном коммите.
3. **Состояние — через команды:**
   - `flint-node current` — код текущего сервера (пусто в режиме без серверов);
   - `flint-sub-update status` — строка последней проверки;
   - `flint-watchdog last` — последний сбой.
   Панель перестаёт читать `/etc/xray/current-node`, `/etc/xray/sub-checked`, `/etc/xray/watchdog-last`.

**Проверка:** все вкладки на компьютере и телефоне (скриншоты демо-скриптом до и после — должны совпасть), все действия в панели на роутере: выбор сервера, VPN вкл/выкл, маршрутизация, свои сайты, свои серверы, подписки, реклама.

**Готово, когда** `panel.cgi` короче примерно на 100 строк, в нём нет путей `/etc/xray/` и нет цепочки `elif` по параметрам.

## Этап 5. Файл на каждый источник серверов (находка 3)

**Новая раскладка**

| Файл | Что в нём |
|---|---|
| `/etc/xray/nodes.d/s1.conf`, `s2.conf`, … | серверы подписки (пишет `flint-sub-update`) |
| `/etc/xray/nodes-custom.conf` | свои серверы (как сейчас) |
| `/etc/xray/nodes.conf` | серверы, заданные вручную (`config/nodes.conf`, `tools/sub2nodes.py`) |

Группа сервера = имя файла. Коды уникальны по всем файлам: при записи подписки занятые коды получают номер (`de2`), как сейчас.

**Шаги**
1. `flint-sub-update`: писать каждую подписку в свой файл; не скачавшаяся подписка не трогает свой файл; удаление подписки удаляет её файл. Удалить `old_block`, `FIRST`, служебную группу `-`, вывод строк `#@`. `build` сводится к пересчёту кодов и записи изменившихся файлов.
2. `flint-node`: `node_files` = `nodes.conf`, `nodes.d/*.conf`, `nodes-custom.conf`; `names` берёт группу из имени файла (`s1`, `own`, `-` для `nodes.conf`). Разбор `#@` удалить.
3. `flint-custom`: убрать пропуск строк `#@`; поиск свободного кода `myN` — по всем файлам.
4. `firewall.user`: читать хосты из всех файлов (через `node_lines` из этапа 2).
5. Панель: карточка на каждую подписку, «Серверы» для группы `-`, «Свои серверы»; группа `*` и `SUBIDS` уходят.
6. **Перенос** в `install.sh`: если есть `nodes.conf` с разметкой `#@` — разложить блоки по `nodes.d/<id>.conf`, строки без разметки отдать первой подписке (если она есть) или оставить в `nodes.conf`; старый файл сохранить как `nodes.conf.bak`.
7. Бэкап и восстановление (`backup.*`, `restore.*`, `deploy.*`): добавить каталог `nodes.d/`; восстановление старого бэкапа без него работает через перенос из шага 6.

**Проверка:** сценарии этапа 0; перенос со старого `nodes.conf` с двумя подписками и строками без разметки; восстановление старого бэкапа (1.1.x) на роутер с новой версией.

**Готово, когда** в коде нет `#@`, `old_block`, `FIRST` и группы `*`, а сценарии и перенос проходят.
