# Аудит качества кода

Строгий аудит поддерживаемости кода Flint VPN: структура, дублирование, границы модулей, размер файлов. Поведение не оценивалось — всё перечисленное работает и проверено на роутере; речь о том, насколько код легко читать и менять.

План исправлений — в [refactoring-plan.md](refactoring-plan.md). Следующий аудит (версия 1.2.0) — [code-quality-audit-1.2.md](code-quality-audit-1.2.md).

## Охват

- Изменения от `v0.7.0` до `91bfd76` (версии 1.0.0, 1.1.0 и «Не выпущено»): подписки, версии, режим без серверов, шапка панели.
- 15 файлов: `kit/files/usr/bin/*`, `kit/files/www/flint/cgi-bin/panel.cgi`, `kit/files/etc/{firewall.user,init.d/xray}`, `kit/install.sh`, скрипты `deploy`/`backup`/`restore`.
- Объём: около +450 / −160 строк.

Размеры основных файлов на момент аудита:

| Файл | Строк |
|---|---|
| `kit/files/www/flint/cgi-bin/panel.cgi` | 523 |
| `kit/files/usr/bin/flint-adblock` | 295 |

Порог в 1000 строк не перейдён ни одним файлом.

## Итог

Как PR это не прошло бы ревью без исправления находок 1 и 2: работающий, но размазанный по скриптам код, появившийся вместе с режимом «без серверов». Находка 3 — главная возможность заметно упростить устройство подписок. Остальное — накопленное дублирование и рост `panel.cgi`.

Сильные стороны: разделение по модулям в целом здравое — подписки в `flint-sub-update`, серверы в `flint-node`, а панель только вызывает команды; весь код проверен на роутере, включая режим без серверов.

## Находки

### 1. Выбор «текущего сервера» продублирован в четырёх местах

**Приоритет: блокер (структурная регрессия).**

Логика «текущий сервер исчез → берём первый → серверов нет совсем → режим без серверов» написана заново в каждом вызывающем скрипте:

| Где | Как |
|---|---|
| `flint-node`, `current()` | `cat current-node` или первый сервер из списка |
| `flint-sub-update`, `commit()` | проверка, есть ли текущий в новом списке; иначе первый; иначе `flint-node "${cur:-apply}"` |
| `flint-custom`, команда `del` | `first="$(flint-node codes \| head -n1)"`, затем `flint-node "${first:-apply}"` |
| `install.sh` | `flint-node use "$DEFAULT_NODE" \|\| flint-node use "$(flint-node codes \| head -n1)"` и отдельный `if`/`else` для пустого списка |

Подпорки `"${cur:-apply}"` и `"${first:-apply}"` появились именно потому, что решение принимают вызывающие, а не владелец понятия. Любое изменение правила (например, «при исчезновении текущего брать `DEFAULT_NODE`, а не первый») придётся вносить в четыре места.

**Как должно быть:** решение принимает только `flint-node apply` (без аргумента): текущий, если он есть; иначе первый, с сообщением; иначе режим без серверов. Явный выбор `flint-node use <код>` остаётся строгим и на неизвестный код отвечает ошибкой.

### 2. Признак «серверов нет» проверяется в 11 местах тремя способами

**Приоритет: блокер (рост «спагетти»).**

| Способ | Где |
|---|---|
| пустой `nodes()` | `flint-node`, `apply` |
| собственный разбор файлов серверов (`$servers`) | `firewall.user` |
| `[ -n "$(flint-node codes)" ]` | `install.sh` (4 раза), `flint-watchdog` |
| пустой `$NAMES` | `panel.cgi` (3 раза) |

Каждая проверка — новая ветка в чужом потоке управления. При этом у системы уже есть естественный инвариант: **`/etc/xray/config.json` существует тогда и только тогда, когда Xray есть что запускать**. На нём уже держится `init.d/xray`, а `flint-node` удаляет конфиг в режиме без серверов.

**Как должно быть:** `firewall.user` и `flint-watchdog` проверяют `[ -s /etc/xray/config.json ]`; после исправления находки 1 в `install.sh` остаётся одна проверка — для итогового сообщения. Панели достаточно `$NAMES`, который она и так строит.

### 3. Группы серверов размечены внутри одного `nodes.conf`

**Приоритет: упущенная возможность сильного упрощения.**

Серверы всех подписок лежат в одном `nodes.conf`, а принадлежность подписке отмечена строками `#@ <id>`. Отсюда целый слой побочной сложности:

- `old_block()` в `flint-sub-update` заново разбирает `nodes.conf`, чтобы достать серверы одной подписки, когда она не скачалась;
- переменная `FIRST`: строки без разметки (из старых версий) считаются серверами первой подписки;
- служебная группа `-` (серверы не из подписки) в `flint-sub-update` и группа `*` с переменной `SUBIDS` в панели — одно понятие под двумя именами;
- разметку `#@` разбирают три скрипта: `flint-node names`, `flint-custom entries` (пропускает), `flint-sub-update` (`old_block`, `build`).

**Как должно быть:** отдельный файл на источник — `/etc/xray/nodes.d/<id>.conf` для подписок, `nodes-custom.conf` для своих, `nodes.conf` для заданных вручную. Группа сервера = имя файла (так уже определяются «свои» по `nodes-custom.conf`). Исчезают `old_block`, `FIRST`, разметка `#@` и группа `*`; не скачавшаяся подписка просто не трогает свой файл. Повторы кодов (`de`, `de2`) по-прежнему разрешаются при записи.

Цена: перенос старого `nodes.conf` при установке, изменение списка файлов в бэкапе и восстановлении.

### 4. Канонические помощники скопированы по скриптам

**Приоритет: дублирование, неверный слой.**

- Функция перевода сообщений `t()` определена в `flint-adblock`, `flint-sub-update`, `flint-watchdog`, а в `flint-node` написана в четвёртый раз — встроенным `if`.
- Фильтр «строки без комментариев» `'^[[:space:]]*(#|$)'` повторяется 6 раз (`flint-node`, `flint-sub-update` ×4, `firewall.user`).
- Разбор хоста из ссылки (`host_of`) и чтение списка серверов дублируются между `flint-sub-update`, `flint-node` и `firewall.user`.

**Как должно быть:** общий `/usr/share/flint/lib.sh`, который подключают все скрипты. Каталог `/usr/share/flint` уже существует (там `vless.awk`).

### 5. `panel.cgi` растёт и знает лишнее о других модулях

**Приоритет: размер и границы модулей.**

До 1000 строк далеко (523), но следующая крупная функция приблизит файл к порогу.

- **CSS** — около 75 строк встроены в каждый ответ. Отдельный `/www/flint/panel.css` отдаётся `uhttpd` статически и кешируется браузером (так уже отдаются `logo.svg` и `icon.svg`).
- **Обработка действий** — цепочка из 26 веток `elif`, каждая проверяет своё имя параметра. Одно поле `a=<действие>` и `case` сделали бы диспетчер плоским.
- **Утечка внутреннего состояния** — панель напрямую читает файлы других скриптов: `/etc/xray/current-node`, `/etc/xray/sub-checked`, `/etc/xray/watchdog-last`. Формат и путь этих файлов становятся неявным контрактом. Лучше, чтобы каждый скрипт отдавал своё состояние командой (`flint-node current`, `flint-sub-update status`, `flint-watchdog last`).

### 6. Мелочи

- `install.sh`: `[ -n "$(flint-node codes)" ] || [ -z "$(flint-sub-update list)" ] || flint-sub-update || true` — цепочка, смысл которой («серверов нет, а подписка задана — скачать») читается с трудом.
- `flint-sub-update`: два файла состояния (`sub-status` — по подпискам, `sub-checked` — общий) и две функции с похожими именами (`status()` и `sub_status()`).
- `flint-sub-update`, `same()`: внутри при каждом вызове заново объявляется функция `strip`.

## Как оценивались находки

Порядок важности: структурные регрессии → упущенные сильные упрощения → рост ветвлений → границы модулей и контракты → размер файлов → модульность → читаемость. Мелкие стилистические замечания сознательно не перечислены.
